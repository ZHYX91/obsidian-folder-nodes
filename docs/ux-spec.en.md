# Folder Nodes — UX specification

## Obsidian consistency

The interface uses native Obsidian Setting, Menu, Modal, Notice, theme variables, icons, and keyboard focus. Desktop targets are at least 36px and coarse-pointer targets are 44px. Settings use the imperative four-tab surface on every supported Obsidian version: General, Homepage, Icons & appearance, and Selection & naming. Declarative settings remain disabled because they bypass this layout. The surface starts with the tab row and does not repeat either a large plugin-name heading above it or the active tab label inside the panel. Tabs retain a baseline-and-accent-underline treatment under host theme overrides, give the active tab a semibold label, keep stable space between the tab row and panel, scroll horizontally at narrow widths, grow with large interface text, and support direction-aware arrow keys plus Home and End. The language dropdown contains `Follow Obsidian`, `简体中文`, and `English`; Follow Obsidian uses Obsidian's current interface language.

## Homepage

When enabled, the Root Node Note is the only homepage. The command palette and Home button in the Node Contents header open that note. Open homepage on startup runs after Obsidian restores the Vault layout. A disabled homepage or missing Root Note produces an explicit notice and never creates a file silently.

## Selection creation

Selected editor text exposes Create Folder Node from selection in both the context menu and command palette. The confirmation modal shows the parent node, final Node Note path, alias, and wikilink together. On confirmation, selected text becomes the new Node Note body and the previewed wikilink replaces the source selection. If the selection, source path, or table structure changes before confirmation, creation stops. Source and Live Preview support a selection inside one Markdown table cell and preview an escaped `\|` wikilink separator. Cross-cell and cross-row selections show a notice and perform no write. The aliases switch does not change the basename, and filename affixes do not change the alias.

The Selection & naming page begins with a compact explanation card showing `[[a]]` → `a/a.md` and `[[a|b]]` → `a/a.md`, followed by the shared aliases switch. In managed scope, normal or modified clicks on an unresolved internal Markdown link create and open the complete Node in the corresponding pane. When aliases are enabled, only the explicit display text `b` becomes an alias; the target `a` remains the Node name and the new body is blank. Existing links are never mutated merely by clicking them. Unmanaged or unsupported targets keep native Obsidian behavior, while a structural conflict produces a notice and no partial Node.

## Explorer Node Tree

File Explorer starts with a pinned Root card that has no disclosure control, cannot collapse or drag, and opens the Root Node Note on click or keyboard activation. The Root icon, Vault name, and Root state occupy a fixed icon slot, flexible name slot, and trailing status slot; a border and accent edge establish hierarchy while the active state still follows Obsidian. Ordinary Folder Nodes likewise keep property visuals in a fixed frameless slot, the name in the native title slot, and states such as Incomplete node, Unmanaged, and Conflict in a trailing pill instead of concatenating them with the name. Complete nodes and the folder half of an incomplete node may use a node visual; Markdown-only incomplete nodes and unmanaged items do not receive a generic file icon. Every icon slot has the same geometry, and default SVG, glyph, emoji, and image sizes cannot alter native row height. Clicking a complete node's folder title opens its Node Note; an incomplete folder keeps Obsidian's native expand/select behavior. The disclosure arrow only expands or collapses, and canonical Node Note rows are hidden. Each File Explorer leaf works independently, including popout windows; the plugin must not observe the whole `document.body`. Dragging must show a before line, into highlight, or after line, and the Vault is not changed before drop. Obsidian's New note/New folder buttons and native folder rename/move/delete menu items remain visible. Beside them, the plugin adds New node to create a folder and matching Node Note atomically, plus distinct node actions such as Contents, Visual, merge, and reorder. Disabling the plugin must remove Root, owned buttons/icons/classes/listeners and restore Explorer order and owned draggable attributes.

## Node Contents View

The sidebar header contains breadcrumbs, optional current-node visual, title, Home, Edit visual, and New child node. Nodes display artwork only for a valid or inherited visual; nodes without one use compact text cards and no large fallback folder. Album uses dense 4:3 thumbnails: ordinary images have no badge, GIFs have a `GIF` badge and are converted to a still frame, and videos use only a static type tile. HEIC/HEIF, audio, and other resources stay in the compact Files list. Unmanaged folder and Markdown rows use the same neutral Unmanaged badge in a shared status column, with Folder or MD in a separate aligned type column. The plugin renders no `<video>` or `<audio>` controls and never autoplays; Open only navigates to Obsidian's file view. Sections collapse and at most 200 items render per batch.

Node, Album, and Files entries open the same Obsidian Menu from right-click, a More actions button visible on hover/focus, and Shift+F10 or the Menu key. Plugin-owned Contents menus may expose the complete node action set because they do not duplicate a native tree menu. File Explorer folder menus keep native rename/move/delete and receive only distinct node actions. A Node Note tab keeps native note-only move/delete/merge; Folder Nodes adds clearly labelled Move/Merge/Delete containing node actions, while native rename synchronizes an unambiguous folder/Note pair. Folder-side incomplete nodes offer Complete node and Set as unmanaged; Markdown-side incomplete nodes offer Convert to Folder Node and Set as unmanaged. The hover/focus primary action matches the menu action, while the state badge itself has no double-click behavior. Unmanaged items offer Manage again; items covered by a name-start rule or unmanaged ancestor direct the user to change that rule. Native create/delete changes only the side that exists and never auto-completes or rebuilds it. Deleting a folder lets Obsidian remove its subtree, including its canonical Node Note. Ordinary-file menus contain open, open in a new tab, reveal in File Explorer, copy link, rename, move, and trash; supported images may also become the current Node visual. Ordinary files, Album entries, and unmanaged folders still accept actions injected by other plugins through `file-menu`. Every failed write produces a fail-closed Notice.

The top 25% of a Node card is a before line, the middle 50% is an into highlight, and the bottom 25% is an after line, matching Explorer semantics. Ordinary Files and Album entries have only into placement and no before/after or ordering metadata. They may drop onto a child Node, the current-node header, or a breadcrumb, then move through Obsidian FileManager after drop. A node cannot enter itself or a descendant, and file-name collisions block writes. Escape, dragend, leaving a target, and failure clear visual state. Nothing changes before drop. Menu move/reorder actions are complete keyboard equivalents. Selection mode may select multiple Album/Files entries to insert or copy links. A single dragged entry can move inside this Contents View; dragging multiple selected entries exports their links only and cannot become a partial multi-file move. Cross-view internal drops are not accepted.

## Visual Picker

The Picker loads the current complete `icon` Text/List instead of opening on a blank input. Users add, remove, and move Vault image wikilinks, `lucide:` candidates, single glyphs/emoji, and `color:` modifiers, or append stable presets. Explorer and Contents previews update with input. Confirmation removes the property for zero entries, writes Text for one, and a flat Text List for multiple. Unknown, multi-grapheme, non-string, or nested values refuse saving with a notice instead of being silently accepted or overwritten. A missing image previews the next local candidate, and inherited visual appears only after the local declaration is fully exhausted. The first valid color colors a glyph or Lucide foreground; emoji and images receive no marker or decoration, and color becomes a centered solid circular swatch only if every base fails. Property icons occupy a fixed frameless slot, whereas the same character in a file name remains plain; glyph weight, size, and color provide the distinction shown by the Icons & appearance guide. File Explorer icons may appear before or after the name or remain hidden. Note-title display is a separate switch; its icon remains a non-editable sibling outside editable `.inline-title`, is offset from the actual first-line title geometry, and realigns on view resize. Glyphs use Obsidian's interface font. The Emoji font control starts disabled while it probes the curated local families, then lists System default plus installed matches only; a retained but unavailable cross-device selection is labeled unavailable and renders through the platform fallback. Its preview includes recent, flag, skin/ZWJ, and family sequences, and the refresh action reruns detection after a font install. CSS variables continue to provide advanced overrides.

## Bulk organization and Health

The plugin has no initialization or adoption state. Once enabled, it immediately classifies structures in managed scope as complete, incomplete, or conflicting, and synchronizes renames only for unambiguous complete pairs. General offers optional Bulk organize incomplete nodes after the unmanaged rules. Its batched Vault scan reports progress, supports cancellation, and skips exact paths, name-start rules, and unmanaged-folder subtrees. The completed preview expands exact leaf-Markdown source/target moves, Node Notes to create, and blocking conflicts; no file changes before confirmation. Confirmation revalidates the preview, applies it, validates the result, and safely stops and rolls back on failure. Health is always strictly read-only. Contents and Explorer use neutral Incomplete node styling; only real pair conflicts use warning styling and recovery actions.

## Unmanaged content

General shows two rule groups: Unmanaged Markdown files and Unmanaged folders. Each group combines exact paths and name-start rules in one list, labels each row by rule type, and offers Add path and Add name-start rule actions together. Rows use natural language such as “Name starts with ‘.’” instead of wildcard notation. `.` and `_` are the default name starts for both groups. The active Vault configuration directory, `.git`, and `.trash` are system-protected. Unmanaged rules stop structural management only; they do not hide files or folders. Exact unmanaged items and shared rules stay in plugin `data.json`, never note YAML.
