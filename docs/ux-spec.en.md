# Folder Nodes — UX specification

## Obsidian consistency

The interface uses native Obsidian Setting, Menu, Modal, Notice, theme variables, icons, and keyboard focus. Desktop targets are at least 36px and coarse-pointer targets are 44px. Settings use the imperative five-tab surface on every supported Obsidian version: General, Management, Icons & appearance, Selection & naming, and Node Graph. Homepage controls are merged into General; unmanaged rules, bulk organization, property migration, and Health are grouped in Management. Declarative settings remain disabled because they bypass this layout. The surface starts with the tab row and does not repeat either a large plugin-name heading above it or the active tab label inside the panel. Tabs retain a baseline-and-accent-underline treatment under host theme overrides, give the active tab a semibold label, keep stable space between the tab row and panel, scroll horizontally at narrow widths, grow with large interface text, and support direction-aware arrow keys plus Home and End. An invalid or newer settings schema produces an explicit read-only warning inside every tab while leaving tab navigation available; all settings controls are disabled and `data.json` is not rewritten. A failed save keeps the latest session values, shows a visible pending row, and offers Retry save. The language dropdown contains `Follow Obsidian`, `简体中文`, and `English`; Follow Obsidian uses Obsidian's current interface language.

## Homepage

When enabled, the Root Node Note is the only homepage. The command palette and Home button in the Node Contents header open that note. Open homepage on startup runs after Obsidian restores the Vault layout. A disabled homepage or missing Root Note produces an explicit notice and never creates a file silently.

## Selection creation

Selected editor text exposes Create Folder Node from selection in both the context menu and command palette. The confirmation shows only Create in, New node, and Alias; disabled aliases explicitly say Do not add, while the final Node Note path and raw wikilink stay out of the default UI. On confirmation, the plugin still uses its pinned Vault-relative wikilink internally, writes selected text as the new Node Note body, and replaces the source selection transactionally. If the selection, source path, or table structure changes before confirmation, creation stops. Source and Live Preview support a selection inside one Markdown table cell; cross-cell and cross-row selections show a notice and perform no write.

The Selection & naming page begins with a compact explanation card showing `[[a]]` → `a/a.md` and `[[a|b]]` → `a/a.md`, followed by the shared aliases switch. In managed scope, normal or modified clicks on an unresolved internal Markdown link create and open the complete Node in the corresponding pane. When aliases are enabled, only the explicit display text `b` becomes an alias; the target `a` remains the Node name and the new body is blank. Existing links are never mutated merely by clicking them. Unmanaged or unsupported targets keep native Obsidian behavior, while a structural conflict produces a notice and no partial Node.

Prefix and Suffix each have a heading. A disabled group hides source, separator, custom text, and timestamp controls; custom text and timestamp format appear only for their matching source. Each timestamp source stores its own validated Obsidian/Moment pattern with a live preview and inline invalid state. One captured `Date` is formatted twice. Schema-2 shared percent-token formats migrate into both groups, and no second runtime formatter remains.

## Explorer Node Tree

File Explorer starts with a pinned Root card that has no disclosure control, cannot collapse or drag, and opens the Root Node Note on click or keyboard activation. Canonical Node Note rows are hidden. If that hidden note is a complete node's only visible direct child, its equal-width disclosure slot shows a passive 4px faint dot with `aria-hidden` and no pointer/focus behavior. Any ordinary file, attachment, visible child node, or session-revealed hidden child restores the native arrow immediately. The plugin never changes Obsidian's expanded/collapsed state. Clicking a complete node title opens its Node Note; incomplete folders retain native expand/select behavior. Each File Explorer leaf works independently, desktop retains before/into/after drag, and Android registers no HTML5 drag/drop listeners. Unload removes the dot and restores every host attribute the plugin owned.

## Node Contents View

The sidebar breadcrumb contains ancestors only and compacts deep paths with a middle ellipsis on one line. The current Node appears once below it as a card that opens the Node Note, so there is no duplicate file-text action. Node Graph, Select content, and New child share the header action area; lower-frequency node actions such as Set icon live under More. Nodes, Album, and Files render only when non-empty with muted trailing counts; if all three are empty, one unified empty state appears. Sections collapse, remember disclosure state for the current Contents view session without writing `data.json`, and render at most 200 items per batch.

Node, Album, and Files entries open the same Obsidian Menu from right-click, a More actions button visible on hover/focus, and Shift+F10 or the Menu key. Healthy Folder Node menus use progressive disclosure: Open, Open in new tab, Create child, and Folder Nodes actions remain direct; Folder Nodes actions opens a grouped panel with Open, Appearance, Structure, and Management sections. The same central action model serves Contents, Graph, native folder, and Node Note surfaces, filtering actions already supplied by that surface. Reorder boundary actions remain visible but disabled, inherited hiding is a disabled source explanation, and subtree-wide unmanaged/delete wording is explicit. File Explorer folder menus keep native rename/move/delete, and a Node Note tab keeps native note-only operations. Problem-node menus stay short and repair-focused rather than entering the complete action panel. The hover/focus primary action matches the menu action, while the state badge itself has no double-click behavior. Unmanaged items offer Manage again; items covered by a name-start rule or unmanaged ancestor direct the user to change that rule. Native create/delete changes only the side that exists and never auto-completes or rebuilds it. Deleting a folder lets Obsidian remove its subtree, including its canonical Node Note. Ordinary-file menus contain open, open in a new tab, reveal in File Explorer, copy link, rename, move, and trash; supported images may also become the current Node visual. Ordinary files, Album entries, and unmanaged folders still accept actions injected by other plugins through `file-menu`. Every failed write produces a fail-closed Notice.

On desktop, the top 25% of a Node card is a before line, the middle 50% is an into highlight, and the bottom 25% is an after line. Ordinary Files and Album entries have only into placement. Cycles and name collisions block writes, while Escape, dragend, target leave, and failure clear visual state. Android shows no drag handle or drop marker and instead uses Obsidian native folder move, Folder Nodes Move/Move up/Move down, and the ordinary-file Move menu. A node moved natively across parents receives a fresh trailing rank when the target parent is manually sorted. Selection mode on both platforms inserts or copies links from multiple Album/Files entries. Cross-view internal drops are not accepted.

## Node Graph

Node Graph is a Folder Nodes workspace view, never an alteration of Obsidian's native Graph View. Its first toolbar row contains title, native search, **Show links**, 2D/3D, and Fit. The second contains Global/Subtree/Local scope and an Expand range menu; narrow windows wrap these two rows without covering the graph. Structure is always the hierarchy. **Show links** is off for a new graph and independently overlays purple dashed resolved canonical-note links, an inline legend, and the visible-link count; an enabled scope with no links shows a lightweight inline message. With the switch off, only the structure skeleton remains. The stable 2D hierarchy defaults to left to right, while settings can use top to bottom; all handle and edge geometry rotates with that direction.

Progressive disclosure controls the structural scene before layout. Global starts with Root and direct children. Subtree starts with the selected node and direct children. Local adds one parent for context. Multiple branches may remain open. If direct collapse, Alt whole-branch collapse, or Collapse to level 1 hides the focused descendant, focus moves to its nearest visible structural ancestor; an already-visible focus is unchanged. Scope, focus, dimension, and **Show links** persist in workspace state, while expansion lasts only for the current graph leaf session. Temporary search expansion and clearing still restore their exact pre-search focus, expansion, and camera snapshot instead of applying the manual-collapse rule.

In left-to-right 2D, each node card reads parent connector, a left visual/connection handle, the body name, a right child-expansion handle, then child connector. The right handle is absent for a leaf and otherwise shows child count and expansion state. Visuals are normalized to the fixed slot and resolve own value, inherited value, then Folder, with Home for Root. A right-handle click toggles direct children; Alt-click expands the complete branch. Card-body click selects, double-click or Enter opens the canonical Node Note, and right-click, Shift+F10, or the Menu key reuses the node menu. Handles and controls expose native tooltips, keyboard activation, focus indication, and explicit accessible names; coarse-pointer targets are at least 44px.

Search uses Obsidian's SearchComponent. Enter chooses the best result, reveals every hidden ancestor, centers the node, and keeps it selected. The first active query snapshots expansion, focus, and camera state; Escape or clearing search restores that snapshot. An external focus request applies the same ancestor reveal. Folder Node and canonical Node Note menus can open and focus an existing graph leaf, open a subtree, or open the local scope.

The Node Graph settings tab contains only a total switch, default dimension, the 2D layout direction, and Canvas/large-graph thresholds. It has no persistent include, exact-node exclusion, or subtree-exclusion editor; File Explorer, Node Contents, and Node Graph all obey the same `hidden=true` subtree token. Schema-1 graph rule arrays disappear during settings migration with one notice and no note writes. Disabling Node Graph removes its command-visible view entries and detaches open graph leaves without changing Obsidian's native Graph. One incrementally refreshed graph index supplies structure, visuals, and canonical-note links; visibility and one shared scene geometry then feed DOM, Canvas 2D, and layered 3D. Large scenes keep constant DOM, preserve every visible structure edge, bound only the optional link overlay, maintain readable 2D zoom, and render distant 3D nodes as dots with full cards on focus or hover. The graph never adds a second Vault scan, polling loop, or graph-covering density notice.

## Visual Picker

The Picker loads the current complete `icon` Text/List instead of opening on a blank input. Users add, remove, and move Vault image wikilinks, `lucide:` candidates, single glyphs/emoji, and `color:` modifiers, or append stable presets. Explorer and Contents previews update with input. Confirmation removes the property for zero entries, writes Text for one, and a flat Text List for multiple. Unknown, multi-grapheme, non-string, or nested values refuse saving with a notice instead of being silently accepted or overwritten. A missing image previews the next local candidate, and inherited visual appears only after the local declaration is fully exhausted. The first valid color colors a glyph or Lucide foreground; emoji and images receive no marker or decoration, and color becomes a centered solid circular swatch only if every base fails. Property icons occupy a fixed frameless slot, whereas the same character in a file name remains plain; glyph weight, size, and color provide the distinction shown by the Icons & appearance guide. File Explorer icons may appear before or after the name or remain hidden. Note-title display is a separate switch; its icon remains a non-editable sibling outside editable `.inline-title`, is offset from the actual first-line title geometry, and realigns on view resize. Glyphs use Obsidian's interface font. The Emoji font control starts disabled while it probes the curated local families, then lists System default plus installed matches only; a retained but unavailable cross-device selection is labeled unavailable and renders through the platform fallback. Its preview includes recent, flag, skin/ZWJ, and family sequences, and the refresh action reruns detection after a font install. CSS variables continue to provide advanced overrides.

## Bulk organization and Health

The plugin has no initialization or adoption state. Once enabled, it immediately classifies structures in managed scope as complete, incomplete, or conflicting, and synchronizes renames only for unambiguous complete pairs. Management offers optional Bulk organize incomplete nodes after the unmanaged rules. Its batched Vault scan reports progress, supports cancellation, and skips exact paths, name-start rules, and unmanaged-folder subtrees. The completed preview expands exact leaf-Markdown source/target moves, Node Notes to create, and blocking conflicts; no file changes before confirmation. A separate Migrate Folder Nodes properties action scans old/new declarations, reports conflicts and non-canonical placement, and only writes after a second explicit confirmation and stale-preview check. Health combines both read-only scans plus icon-shape diagnostics and never offers a write action. Contents and Explorer use orange Incomplete for repairable gaps and red Conflict for blocking pair ambiguity.

## Unmanaged content

A complete node action panel offers Hide node and subtree or Unhide node; an inherited-hidden descendant shows only a disabled source explanation. An explicitly hidden root shows a non-interactive Hidden text badge when the subtree is revealed, never a per-node eye or direct-write control. Inherited-hidden descendants are muted with a “Hidden by X” tooltip and do not repeat a badge on every row. The Root-row eye and command palette expose the same session switch; Apply hidden markers in General is the persistent master switch. Mobile behavior cannot depend on hover, and actionable controls retain at least 44 px touch targets. Unmanaged items show only their gray Unmanaged badge and never a Hidden badge; Manage again first warns when their own YAML or an ancestor marker will hide them again.

General shows two rule groups: Unmanaged Markdown files and Unmanaged folders. Each group combines exact paths and name-start rules in one list, labels each row by rule type, and offers Add path and Add name-start rule actions together. Rows use natural language such as “Name starts with ‘.’” instead of wildcard notation. `.` and `_` are the default name starts for both groups. The active Vault configuration directory, `.git`, and `.trash` are system-protected. Unmanaged rules stop structural management only; they do not hide files or folders. Exact unmanaged items and shared rules stay in plugin `data.json`, never note YAML.
