# Folder Nodes — Testing strategy

## Automated gates

`FakeObsidian` derives normal metadata from source with the independent `yaml` parser. `metadataUpdates: deferred`, `modifyEvents: deferred`, explicit cache overrides, and `failNext()` model delay or failure separately. The fixture's own contract tests check source, metadata and notifications for `modify`, `process`, `append`, and `processFrontMatter`; it does not simulate the full host. `tests/helpers/frontmatter-oracle.ts` compares YAML values and the unchanged body, including unknown tokens containing quotes or comments. Settings deletion tests click rendered rows with pending saves, and prompt tests send composition/Enter events through the real input handler. Keep source-string checks for architectural constraints; use behavior assertions for user actions.

`npm run check` pins Node/npm, then runs lint, formatting, bilingual-document contracts, strict TypeScript, coverage, production bundle, and release-layout checks. The numeric coverage gate includes Core, settings data, NodeService, Explorer adapter/host ordering, production Node Graph paths, RuntimeStyles/Presentation, and other critical runtime code already backed by behavior tests while retaining statements 80%, lines 80%, functions 75%, and branches 70%. A separate `npm run test:coverage:inventory` run reports every production `src/**/*.ts` file except declarations, so runtime shells such as `plugin.ts`, `settings-tab.ts`, and imperative modals appear in the inventory, with uncovered code visible rather than omitted without lowering the established gate to hide that debt. Coverage exposes blind spots but does not replace behavior regressions or real-host evidence. Tests cover paths plus Windows reserved names and grapheme-safe truncation, selection naming, safe table-cell aliases, cross-cell rejection, unresolved-link target and display-alias planning, Visuals, malformed frontmatter boundaries, non-Markdown bulk-organization collisions, exact-path/name-start unmanaged rules, protected system folders, deep settings normalization, curated Emoji-font validation and fallback stacks, the canonical/legacy property matrix, sparse ordering including order-preserving full re-ranking, explicit placement gaps, and incremental reverse references. NodeService uses an in-memory Vault/FileManager behavior fixture covering serialized creates, transactional explicit-path Node creation and rollback, link-safe rename/move, target-rank reconciliation after native cross-parent moves, note-only move/delete, synchronized folder/canonical-note rename, folder-side and Markdown-side incomplete nodes, continuous classification without initialization, ignored-subtree moves, bulk-organization and property-migration TOCTOU/post-commit validation, merge conflicts, rollbacks, and lifecycle abort after an in-flight write. Synchronous and asynchronous structural scanners must produce equivalent plans, and cancellation must perform no write. VaultOperationCoordinator tests lock serialization after failure, recursive event attribution, and TTL. UI/runtime tests lock Explorer-surface start/stop cleanup, Root eye state/click separation, no mobile draggable ownership, retained native create controls plus New node, incomplete/unmanaged/conflict states, the grouped action panel, note-title icons outside editable title text, measured title-icon alignment, visual-kind font classes, local Emoji-font detection failures, cross-document runtime font updates, disclosure selectors, canonical sibling-gap indicators, structural-versus-ordering drag intent, drag payload, Shift+F10/Menu keys, and the settings hierarchy/explanation cards; source architecture contracts prohibit a global body observer, `vault.rename`, and Contents-wide `resolvedLinks` scans.

Node Graph tests import the real production entry and exercise registration, enable/disable, leaf reuse/close, state migration, and teardown rather than relying on source-string assertions. Pure behavior fixtures cover all three progressive defaults, root/local boundaries, multiple simultaneous branches, direct/Alt/range expansion, collapse to level 1, session-only expansion, old relation migration, search snapshot restoration, external focus, node-body open/menu behavior, Tooltip/keyboard/ARIA, Visual fallback, left-to-right/top-to-bottom structure anchors, independent link anchors, structure edges surviving link LOD, and one RuntimeStyles authority. Narrow-screen, coarse-pointer, and synthetic touch coverage protects Android-compatible code without being represented as real Android host evidence.

Regressions additionally inject a concurrent closed-file edit, an unsaved open editor, a same-path TFile replacement, and a same-path folder replacement during rollback. Settings-save tests delay and fail earlier persistence calls to prove snapshot isolation, ordering, and recovery of the queued latest state.

The selected-file aggregate thresholds are distinct from whole-source inventory. Independent file thresholds additionally protect `node-service.ts`, `explorer-events.ts`, and `settings.ts`; their values are declared in `vitest.config.mts`. The document event registry, `settings-tab.ts`, and `prompt-modal.ts` are included in the numeric gate; the prompt also has a file threshold. Inventory alone does not impose a threshold on `plugin.ts` or `contents-view.ts`.


Selected-text regressions invoke the production command and editor menu, the confirmation modal or direct path, and NodeService with an in-memory Vault. They assert the real FileManager call arguments after target creation, transparently pass prescribed host outputs for three path formats and two syntaxes through prose and table cells, and cover literal display text, duplicate basenames, aliases, source/range/table/editor drift, creation conflicts, repeated submission, generation/replacement errors, and rollback refusal after a user edit. These tests do not emulate Obsidian’s path-selection algorithm or prove its live cache and Source/Live Preview rendering behavior.

Creation-cleanup regressions claim the new file during the final asynchronous read with clean, dirty, multiple, save-less, and unloading Markdown panes, and replace the TFile at the same path. Assertions verify retained content and localized path/reason feedback. Canvas keyboard tests cover both layout directions and no-wrap boundaries. These simulated interleavings do not establish real host editor or screen-reader acceptance.

Merge regressions assert zero mutations for resolved source-note WikiLinks and embeds in source bodies and moved descendants, including parsed Text/List properties with YAML escapes, basename lookup, aliases, table-cell escaped aliases, headings, and block references; literal code/comments and unrelated links remain accepted. Visual regressions invoke the production picker and cover menu, mutate file/folder identity or the original icon, and delay the actual frontmatter callback until unload. Keyboard tests retain focus after list reorder/deletion. Static-asset tests overlap real filesystem copies, simulate editor atomic saves, and drain or report watch shutdown errors. These are automated adapter/DOM/filesystem checks, not desktop or Android acceptance.

## Performance

`npm run test:browser` bundles the production Canvas renderer and tooltip CSS with only Obsidian DOM convenience helpers, then runs real Chromium layout using installed Chrome/Chromium/Edge or `CHROME_BIN`. It verifies hidden-to-new-node and visible-to-new-node scroll reset, same-node scroll retention, Escape/reopen, both scroll axes and resize/reopen. The browser uses a fresh temporary profile and closes before that profile is removed. This check complements the simulated DOM tests and does not certify native Obsidian interaction.

The same browser check runs the production Explorer reveal adapter against a clipped drawer with a scrolling file tree and an absolute toolbar, for eleven layout groups in total. Real fractional toolbar edges within the reveal tolerance must move the obscured row above the toolbar; a gap beyond that tolerance must not trim the viewport. Unit tests also preserve exact fractional rectangles and mirrored top-edge cases.

Host key-scope regressions model the host's window-capture shortcut route before DOM keydown. They cover Canvas, overlay and DOM card Ctrl/Cmd+Enter, parent-scope fallback for search/toolbar/expand/icon/details/other-view focus, repeat/composition refusal, close/reopen without duplicate handlers, and a separate owning document. Alt+Enter covers actual branch expansion/collapse through both existing handle types and parent fallthrough for body/Canvas/search/toolbar/icon focus. Native Obsidian acceptance still verifies actual host dispatch, new-leaf navigation and handle activation.

Additional lifetime regressions resolve and reject the production reveal caller after unload/restart and retain genuine current errors. Overflow-details DOM tests cover non-overlap with the trigger at the top, middle and bottom of a narrow viewport, original-node click/double-click/context-menu callbacks, pointer entry across empty space, keyboard focus, Escape, fresh scroll positions, and clearing stale hover on viewport resize. Timer tests cover cancellation on entry, focus, replacement, resize and destruction, the owning document window and a retained callback after destruction. Geometry doubles remain separate from real font layout, native hit-testing and scrolling evidence.

Explorer reveal regressions drive the real adapter's asynchronous continuations through stop during leaf materialization, stop and restart, unload during native reveal, a newly hidden target, and stopped refresh/delayed decoration. Canvas resource regressions drive the production renderer with deterministic Canvas/Image/animation-frame doubles across 256, 257, and 513 distinct visuals, shared visuals, mixed load/error completion, panning, palette changes, and destruction, asserting no new images or frames after input settles. Tooltip regressions use production pointer events and measured-size doubles for narrow panels, all corners, long Chinese/Arabic paths, right-to-left layout, and enlarged fonts. Controlled timers cover returning from details to the node overlay by pointer or focus; Canvas and overlay Enter/Space, including Ctrl/Cmd+Enter, must dismiss details and cancel timers before the open callback. These simulations do not establish actual host font layout, frame rate, or Android behavior.

Mobile reveal geometry tests cover overlapping versus non-overlapping/hidden toolbars, clipped drawer viewports, delayed row materialization during a finite animation, cancellation and safety expiry after an animation pauses, zero-speed/infinite animations, late completion, request replacement and adapter restart. The isolated provider can record an explicit Reveal in File Explorer action from a native menu or the node-actions modal, including nested icon/label targets in either interface language. It records the canonical folder row, scroll viewport and toolbar bounds, ignores unrelated or disabled actions, and removes its capture listener and pending frames on disposal; recording geometry assigns no verdict.

Node merge link checks cover unsafe inline and multiline reference destinations in the source
body and moved Markdown descendants, unchanged attachment targets, and literal code/comments.
Final-read regressions inject unload, newly opened editors, file replacement, and new source
children after asynchronous descendant reads. An earlier descendant changing during a later read
must also prevent trash dispatch. The `node-merge-link-safety` acceptance scenario exercises the
same refusal, successful attachment move, editor-open race and actual plugin unload in isolated
desktop and Android hosts; provider setup and observations do not assign a product verdict.

Automation locks canonical `folder-nodes` token parsing/writing/deletion, published legacy reads, equivalent dual values, fail-closed conflicts/invalid/duplicate YAML, source-preserving explicit migration, stale-preview rejection, descendant inheritance, Root/incomplete/unmanaged write rejection, unmanaged and master-switch precedence, merge non-copying, Explorer/Contents/Graph projections, Root-eye session reveal, and graph metadata invalidation. Isolated-Vault acceptance also covers both languages, no hover dependency on mobile, a Hidden text badge on an explicit hidden root, muted inherited-source feedback, master-off preserving YAML, reload resetting the session switch, and no effect on Obsidian Search, Quick Switcher, backlinks, native Graph, or direct access.

The quick gate covers 10,000 and the large gate 100,000 direct Child Nodes; a normal reorder plan must finish within two seconds and create one property patch. Crowded ranks fall back to re-numbering the full sibling sequence while preserving the requested order; the sparse-rank single-patch target applies only when a safe gap exists. The reverse-reference benchmark builds quick 20,000/large 100,000-source indexes and applies 1,000 incremental removals. The incomplete-node scan checks near-linear planning and exact counts for quick 20,000/large 100,000 entries. RefreshScheduler tests combine 10,000 requests into one batch. In one deterministic serial worker, the Node Graph benchmark builds the real production GraphIndex for quick 20,000/large 100,000-node fixtures, then applies 32/128 non-nested dirty roots in one incremental refresh. Quick initial build and refresh each have a 2-second threshold; their large equivalents each have a 6-second threshold. Search-candidate aggregation plus an exact query has 1-second quick and 3-second large thresholds. The same refreshed snapshot is fully expanded through topology, VisibleScene, model aggregation, and 2D layout, with 4-second quick and 6-second large thresholds; pure 3D layout plus one 1920×1080 projection has 2-second quick and 5-second large thresholds. These deterministic computation gates expose linear regressions but do not prove interactive Canvas frame rate or host UI responsiveness. Separate GraphIndex behavior tests lock one initial inventory, path-targeted subtree refresh, sibling order, link-only invalidation, and exact scan counters. Those counters prove that scope, search, expansion, dimension, and **Show links** do not repeat a Vault-wide inventory. Full expansion keeps DOM node counts constant, preserves all visible structure edges, and applies the configured limit only to link edges. Contents View paginates Nodes, Album, and Files independently at 200 entries per batch. Album images draw once from resource URIs to canvas, and ordinary files do not read binary bodies.

## Isolated-Vault host acceptance

Explorer expansion/collapse anchoring uses the dedicated `explorer-disclosure-anchor` scenario. The acceptance provider's `Prepare long-list disclosure diagnosis` command creates 120 siblings and a central branch with 498 children, and starts frame recording in one operation; the initial short list cannot substitute for this scenario. The recorder tracks the clicked row directly, capturing a baseline before the host click handler and at least 750 ms of subsequent frames, scroll height and headroom at both boundaries. Only nonempty, complete observations with `middleViewportEligible=true` qualify for middle-viewport anchoring checks; empty frames, missing rows and boundary samples cannot count as a middle-viewport pass. Compare `topRange` and `finalDelta`, and report boundary clamping and native behavior with the plugin disabled separately. With the plugin enabled, bottom-boundary clicks must also stay within one CSS pixel; retained space shrinks when scrolling upward and must never grow from downward scrolling.

Select representative acceptance on the exact candidate by change impact. Desktop interaction, settings or lifecycle changes require relevant real-host scenarios; mobile interaction or shared runtime behavior affecting mobile requires relevant Android emulator scenarios. Documentation-only or host-independent logic changes may omit hosts with a recorded reason. Confirmed serious product defects affecting a release block that release. Missing host/tool evidence stays unverified and is assessed by risk; it does not automatically block publication or add a separate approval step. Claim acceptance only for observed passing scope. The full host matrix is not required for every release, and CI does not automatically enforce host coverage. Skipped, failed, and incomplete coverage must be recorded honestly and must not be promoted into a claim that the corresponding host layer passed. ## Themes and accessibility

Check at least default light, default dark, and one third-party theme. Keyboard checks cover all five settings tabs, modal/action-panel buttons, Contents cards/rows, More actions, context-menu keys, breadcrumbs, the Root eye, and the Node Graph visual/body/child-handle controls. Drag has equivalent menu move/reorder actions, and coarse-pointer targets are 44px. English and Chinese must not truncate critical buttons or node titles. Follow Obsidian must match Obsidian's current interface language. Images use empty decorative alt text or filename alt text. The Root row is checked for one idempotent insertion, no disclosure control, separate keyboard activation for Root and eye, accurate pressed state, and active state. Explorer and title icons are checked for Incomplete node, Unmanaged, and Conflict badge contrast, glyph/CJK/emoji font fallback, size, vertical and horizontal alignment, and name spacing at multiple UI scales. Node Graph additionally checks tooltips, visible focus, explicit accessible names, dashed-link contrast, left-to-right/top-to-bottom handle rotation, and toolbar wrapping without covering the graph.

## Android mobile acceptance

Every `isDesktopOnly: false` candidate must retain Android-compatible code and CSS, with automated narrow-screen, coarse-pointer, and touch coverage. When mobile behavior is affected, representative host regression uses the current Android 15/API 35 emulator and a disposable Vault to cover relevant scenarios from plugin load, File Explorer/Contents, native moves, menus, settings persistence, Node Graph scopes/handles/search/2D/3D, narrow layout, touch targets, file deletion settings, and disable cleanup. Android physical devices and iOS are out of scope.

## Production deployment

Public-release hard gates are `npm run release:check`, exact version/tag/commit identity, Candidate Bundle source and transport verification, public-asset integrity, build provenance/attestation, and hosted-byte post-verification; real-host acceptance remains a separate evidence layer. A production Vault requires explicit authorization for its exact path. Confirm Obsidian is stopped, preserve `data.json`, replace only `main.js`, `manifest.json`, and `styles.css`, and compute SHA-256 for candidate and deployed files. Production deployment is not acceptance; the user's manual acceptance result is recorded separately.
