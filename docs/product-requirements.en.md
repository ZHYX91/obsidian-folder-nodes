# Folder Nodes — Product requirements

## Product model

A complete Folder Node is a folder with exactly one same-named Node Note, `A/A.md`; its structural identity remains that current normalized pair. A managed folder or Markdown without its counterpart is an incomplete node that the user may complete or mark unmanaged. Root may have its optional Node Note at the Vault root. Folder Nodes writes no permanent ID, `_pkwf`, path, parent, name, node type, or complete child list.

## Folder Nodes property and ordering

Folder Nodes owns one flat Text List named `folder-nodes`. It contains only non-default `key=value` tokens: `order=manual` on a parent Node Note, a sparse positive `rank=1024`-style token on each direct Child Node Note, and `hidden=true` on a hidden subtree root. Token order is canonical—order, rank, hidden—while syntactically valid unknown future tokens are preserved. Natural name order, absent rank, and visible state write nothing; an empty list is removed. Natural ordering uses normalized names. A normal manual reorder writes only the moved child; local rebalance is bounded to 64 nodes. Missing or duplicate ranks use normalized basename and path as deterministic tie-breakers. Rename retains an existing rank, and a new child in manual mode appends by default.

Published fields `folderNodeChildrenSort`, `folderNodeSiblingRank`, and `folderNodeHidden` remain compatibility-readable. An explicit Management action scans all Markdown without writing, reports canonical, legacy, redundant, conflicting, non-canonical, and invalid-icon declarations, then previews exact migration targets. It never migrates at startup. Commit rescans and fingerprints every target, preserves unrelated frontmatter/body/BOM/line endings and unknown future tokens, validates afterward, and rolls back exact changes on failure. Equivalent dual values may normalize; conflicting, invalid, duplicate, malformed, or changed inputs fail closed. Users must update every device before committing a migration.

## Node operations

Users can create, rename, move, merge, safely delete, and reorder complete nodes. On desktop, Explorer and Contents child-node drag placement mean before, into, or after: same-parent placement reorders, and cross-parent placement reparents and reorders. Android does not enable HTML5 drag-and-drop; it uses Obsidian's native folder move plus the plugin's Move, Move up, and Move down actions. After a native cross-parent move, the plugin assigns the child a fresh sparse rank when the target parent uses manual order instead of carrying a stale source-parent rank into that order. Every structural write must be serialized, rename/move must use Obsidian FileManager, and multi-step writes must preflight and roll back on failure. Conflicts, cyclic moves, and ambiguous merges fail closed. Obsidian's native New folder and New note actions remain visible beside New node: the native actions create an incomplete folder or Markdown half, while New node creates the complete pair atomically. File Explorer folder move/delete acts on the whole subtree; a Node Note tab's move/delete/merge acts only on that Markdown file and may leave an incomplete folder. Rename is the synchronization exception: renaming either an existing Node Note or its folder updates the other half. Explicitly labelled containing-node actions handle whole-node intent from a Note tab. Root cannot be renamed, moved, or deleted as a complete node. Folder Nodes creates blank Node Notes; content templating belongs to dedicated template plugins.

## Selection creation

Editor commands and context menus create Child Nodes from selected text. The confirmation shows only the creation location, new-node basename, and whether an alias will be added; it does not expose the final Node Note path or raw wikilink. On confirmation, the plugin still uses its pinned Vault-relative wikilink internally, writes the selected text as the new Node Note body, and replaces the original selection transactionally. A changed selection, source file, or table structure stops the write. A single Markdown table cell is supported in Source and Live Preview: the generated wikilink uses an escaped `\|` alias separator. A selection that crosses an unescaped cell boundary or table row fails closed before creating anything. In this flow, aliases use only selected visible text; prefixes, suffixes, independent separators, and timestamps affect only the basename. Prefix and Suffix each store a validated Obsidian/Moment timestamp format but format one captured creation instant. Legacy `%Y%m%d-%H%M%S` settings migrate once to `YYYYMMDD-HHmmss` in both groups without changing output.

In managed scope, clicking an unresolved internal Markdown link creates the complete Node directly instead of first creating a leaf note. `[[a]]` creates a blank `a/a.md`; explicit Vault paths create every missing complete ancestor Node transactionally. When the shared aliases setting is enabled, `[[a|b]]` writes the explicit display text `b` to the new Node Note's `aliases`; without display text or with the setting disabled, it writes no alias. Unmanaged folders, unmanaged leaf-note paths, unsafe or non-Markdown targets, and links outside Markdown views remain under Obsidian's native behavior. External and third-party creation is never auto-converted; users may invoke Convert to Folder Node explicitly. Conflicts fail closed.

## Homepage and unmanaged boundaries

A complete, managed, non-Root node may store `hidden=true` in its `folder-nodes` list. The marker affects descendants without copying YAML into them; removing the token clears an explicit hide. Hiding projects only into Folder Nodes-owned File Explorer folder rows, Node Contents, and Folder Nodes Graph; it does not change Obsidian Search, Quick Switcher, backlinks, native Graph, WikiLinks, or direct access. The plugin setting `hiddenNodesEnabled` defaults on; turning it off shows every hidden node without changing YAML. A trailing eye button beside the pinned Root row and the command palette toggle session-only reveal across every window and all three projections, then reset after reload. Unmanaged overrides hidden: unmanaged content remains visible with only its gray Unmanaged badge and no Hidden badge, and Manage again warns when a surviving marker will hide the node again.

The Root Node Note is at the Vault root and uses the Vault name with illegal filename characters sanitized as its basename. Users may make it a homepage, open it by command or from Contents View, and optionally open it after Vault layout restoration. Contents resolves the current node from the active file's owning folder and falls back to Root when no file is active. File Explorer always exposes Root as a pinned, non-collapsible row distinct from ordinary nodes. General owns language, hidden-marker behavior, and homepage controls. Management contains two unmanaged rule groups for Markdown files and folders, preview-first bulk organization and property migration, and read-only Health. Both rule groups accept exact Vault-relative paths and plain-language name-start rules, with `.` and `_` as defaults. Unmanaged rules stop node classification, bulk organization, and structural repair but do not hide content. The active Vault configuration folder, `.git`, and `.trash` are always protected; root `AGENTS.md` and `CLAUDE.md` are unmanaged Markdown paths by default.

## Node Visual and Contents View

`icon` is the only Node Visual property. It uses Obsidian-Properties-compatible Text or a flat Text List and never a nested object. Base candidates are Vault image wikilinks, known Lucide icons, or one visible extended grapheme (letter, symbol, or emoji). The first actually renderable base wins; a missing image continues to later local candidates. The first valid `color:` item colors Lucide/glyph foregrounds. Emoji, raster images, and SVG preserve their pixels without an added marker, background, or border; color becomes a centered solid circular swatch only when every base fails. File Explorer is the only global Node Tree and starts with the pinned Root row. When a complete node has no visible direct content beyond its hidden canonical note, an equal-width passive dot replaces its useless disclosure arrow; the native arrow returns as soon as visible content appears. The sidebar browses direct contents through non-empty Nodes, static Album, and compact Files sections with independent paging, or one unified empty state. Ancestor-only breadcrumbs and one clickable current-node card avoid repeating identity. Node Graph, content selection, and New child share the header action area; low-frequency node actions use More. Section disclosure state lasts for the current view session. Desktop retains drag placement, while Android uses menus or native move and exposes no draggable elements.

## Node Graph

Node Graph is a plugin-owned workspace view that does not alter Obsidian's native Graph View. Structure is always the directed parent-child skeleton. **Show links** is an independent overlay, off by default for a new view; old workspace Structure state migrates to off, while Links and Hybrid migrate to on. Resolved canonical-note links are visually distinct, do not reposition the structural layout, and add direct link neighbors to Local scope only while the overlay is enabled. The view supports stable left-to-right or top-to-bottom 2D and depth-layered 3D from one filtered scene.

When a manual collapse hides the focused descendant, direct collapse, Alt whole-branch collapse, and collapse-to-level-1 move focus to the nearest visible structural ancestor. Search expansion and clearing still restore their exact pre-search focus and expansion snapshot.

Node Graph has no persistent include, single-node exclude, or subtree-exclude rules. The runtime Global/Subtree/Local scope controls only the current view, while the same `hidden=true` Node Note token prunes complete subtrees before graph model and layout. Settings retain only enablement, default dimension, 2D direction, and large-graph limits. Schema-1 rule arrays are discarded during the explicit settings-schema migration with a notice and never rewrite notes.

Visibility is progressively disclosed before layout. Global starts with Root and level 1. Subtree starts with the selected node and direct children. Local adds one parent for context, starts with the selected node and direct children, and allows deeper expansion only inside that selected node's complete subtree. Users may keep several branches open, toggle direct children from a node handle, use Alt to expand one complete branch, or expand 1, 2, 3, or every descendant level from the current range anchor and collapse back to level 1. Full expansion has no second confirmation. Scope, focus, dimension, and **Show links** persist in workspace state; per-scope branch expansion and active-search snapshots are session-only and reset after restart.

Every node has a normalized visual/parent handle, a body that selects and opens its canonical Node Note, and a child handle that is absent for leaves and otherwise reports child count and state. Own visual, inherited visual, Folder fallback, and Root Home fallback share one fixed slot. Search uses Obsidian's native SearchComponent, reveals hidden ancestors for an internal or external focus, centers the result, and restores the pre-search expansion/focus/camera snapshot when cleared. All controls have tooltips, keyboard access, explicit accessible names, and 44px coarse-pointer targets.

The complete graph catalog is built once and refreshed incrementally from node, Metadata Cache, reverse-reference, and refresh-batch changes. Scope, expansion, search, dimension, and link-display changes filter that catalog instead of rescanning the Vault. Large graphs use constant-DOM Canvas scenes, preserve all visible structure edges, bound only the optional link overlay, keep 2D at a readable minimum zoom, and show distant 3D nodes as dots with full cards on focus or hover. Dense-state information stays in the toolbar or status area and never covers the graph.

## Structural safety

Folder Nodes has no initialization or adoption state. Once enabled, it immediately classifies complete, incomplete, unmanaged, and conflicting structures, and automatic rename synchronization applies only to unambiguous complete pairs. Native creation never auto-completes or moves content. Missing folder and Markdown halves both use an orange Incomplete state with explicit complete and Set as unmanaged actions; true pair conflicts use a red Conflict state and fail closed. Optional bulk organization uses a cancellable batched read-only scan, lists every create, move, skip, and block path, revalidates before commit, validates afterward, and rolls back any failed step. Property migration is a separate explicit preview-and-confirm operation. Health combines structure, Folder Nodes property, and icon-declaration findings and remains strictly read-only with no write button. Complete-node deletion uses system trash. The plugin makes no network requests.

## v1 boundary

v1 excludes remote image fetching, inline SVG recoloring, automatic initials from node names, nested `icon` objects, PDF first-page thumbnails, HEIC/HEIF preview, video frame extraction, inline animation/video/audio playback, ordinary-file independent ordering, transactional multi-file moves or cross-view internal drops in Contents View, a second complete directory tree, alternate Node Note naming, complex merge-conflict UI, and arbitrary property inheritance.
