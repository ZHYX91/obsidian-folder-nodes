# Folder Nodes — Architecture

## Identity and persistence

A complete node's current identity is its normalized Vault folder path and `A/A.md` structure; no stable ID exists. Either side missing its folder or same-named Node Note is immediately classified as an incomplete node, without a second hidden identity or any initialization/adoption state. Folder Nodes actively uses `aliases`, `icon`, and one plugin-owned `folder-nodes` Text List. Its canonical tokens are `order=manual`, a positive integer `rank=N`, and `hidden=true`; defaults are absent and an empty list is removed. `aliases` and `icon` are shared content conventions, while `folder-nodes` is the plugin structural contract. Homepage preferences, icon placement, naming rules, exact unmanaged paths, and name-start rules stay in plugin `data.json`, never note YAML. A Node Graph leaf serializes only scope, focus, dimension, and whether links are shown in Obsidian workspace state. Per-scope branch expansion and active-search snapshots remain in memory for that leaf and are never written to `data.json`, note YAML, or restored after restart.

## Layers

The `folder-nodes` list is protected structural metadata and never copies from a merge source. NodeService `children()` continues to return the complete managed structure; visibility projections use `unmanaged || !hiddenNodesEnabled || showHiddenNodesThisSession || !effectiveHidden(node)` and walk upward to the nearest canonical or compatibility-read hidden source. Explorer, Contents, and Graph share that rule, with Graph pruning hidden subtrees before model and layout. Only the persistent master switch enters the current schema-3 `data.json`; session reveal remains in memory. Compatible unversioned, schema-1, and schema-2 settings normalize to one schema-3 snapshot without touching notes; deprecated graph rule arrays are discarded with a reported count.

Property resolution reads `folder-nodes` plus published legacy `folderNodeChildrenSort`, `folderNodeSiblingRank`, and `folderNodeHidden`. Equivalent dual values are redundant; conflicts and invalid known values fail closed. The structural-property and generic-scalar source patchers accept only unindented top-level block mappings: nonzero root indentation, flow-mapping/sequence roots, explicit complex mapping keys, and root scalars fail closed without modifying source bytes. Ordinary block mappings preserve plain-scalar punctuation, quoted values, and inline or multiline flow values, including anchors and tags. Multiline value boundaries exclude nested keys from top-level reads, and scalar replacement removes the complete previous value. The source patcher owns only these exact top-level keys, detects duplicate/quoted/unterminated ambiguity, preserves BOM and line endings, retains unrelated YAML/body plus valid unknown future tokens, and writes canonical token order. Property migration is never a startup effect: its read-only scan fingerprints exact sources, an explicit commit rescans, pins TFile identity and the current unsaved editor where applicable, validates afterward, and rolls exact changed text back on failure.

Core handles paths, naming, unmanaged boundaries, organization plans, reference indexes, sparse ordering, minimal frontmatter patches, visual declarations, and pure graph visibility/geometry. Naming Core validates the public Obsidian/Moment subset and receives a timestamp formatter; actual `moment(date).format(pattern)` remains at the Obsidian adapter boundary. Adapters encapsulate Vault, Metadata Cache, File Explorer, resource URIs, and Node operations. VaultOperationCoordinator independently owns structural-write serialization and internal event attribution. Presentation contains host-DOM renderers shared by Explorer, settings, and UI so those layers do not cross back into their callers. UI/App owns localization, settings, commands, menus, modals, Visual Picker, Contents, Node Graph state/rendering, and batched refresh scheduling. Node Graph stays within the bounded `GraphIndex → ViewState → VisibleScene → renderer` flow instead of becoming a plugin-wide data abstraction. The public repository does not depend on the local workspace or a personal Vault.

## Ordering engine

Natural mode uses Unicode-normalized, numeric-aware basename order and writes no token. Manual child order is an explicit per-parent mode: switching a complete parent to manual writes `order=manual` and materializes its current natural child order as sparse positive `rank=N` tokens at gaps of 1024. A normal placement patches only the moved child when a safe gap exists. If ranks are missing, duplicated, exhausted, or too close to the safe-integer boundary, the planner first fixes the desired sequence and then reassigns ranks for that complete sequence without re-sorting it. Structural reparenting never switches a natural parent to manual. Restoring natural order removes only the parent mode token; inactive child ranks are ignored and do not revive an old sequence if manual mode is enabled again.

## Node operations

NodeService treats create, rename, move, explicit placement, merge, repair, and trash as serialized recoverable structural operations; every rename or move goes through Obsidian FileManager to preserve links. Move and placement reject self and descendants, and relative placement recomputes parent/index inside the same transaction. Each multi-step operation preflights cached and on-disk targets and keeps reverse-order rollback actions; an incomplete rollback returns an aggregate failure containing both the original and recovery errors instead of reporting success. Merge preflights target-path and frontmatter conflicts; target properties win, non-conflicting source properties join the target, resources move, source body is appended, and the source is deleted according to Obsidian’s file-deletion setting. Note-only move/delete is allowed and leaves the containing folder untouched. External rename reconciliation synchronizes an existing Node Note/folder pair in either direction, but never invents a missing Note. Root cannot be renamed, moved, or deleted as a complete node. New Node Notes are blank; Folder Nodes does not execute content templates.

Merge freezes child paths and parents before preflight. Final validation observes Vault modification events across both asynchronous note reads, then synchronously checks both note identities, editor states and remaining source structure. An observed change aborts before trash dispatch. Dispatching the final FileManager trash operation is the commit boundary; unloading afterward does not cancel that host operation. The temporary modification listener is released on success or failure.

Structural metadata patches use the current unsaved Markdown editor when exactly one matching view exists. With no matching editor, they run through `Vault.process`; multiple matching views or a changed file binding refuse the write. Both paths pin the original TFile and path, revalidate immediately before commit, and reject concurrent replacement or content changes. Rollback closures retain original object references and verify owned content before mutation. Forward metadata callbacks and native rename continuations also recheck the active service immediately before dispatch. Writes already accepted by the host return their receipt before unload cancellation is evaluated; exact-content compensation remains permitted after disposal. Settings persistence uses schema 3 and normalizes compatible unversioned, schema-1, and schema-2 data to one canonical schema-3 snapshot. The schema-2 shared legacy `%` timestamp format is converted into independent Moment prefix/suffix formats, while deprecated graph rule arrays are discarded and reported; an invalid or newer explicit schema opens read-only without rewriting unknown fields. Its local serialized queue captures immutable snapshots, retains the latest failed snapshot for Retry, and appends one final compatible snapshot during unload so an older write cannot finish last.

CreatedNodeRecovery owns creation receipts and compensation sequencing; NodeService supplies the file identity, source, and write ports. After the final asynchronous source read, cleanup synchronously rechecks identity and rejects any Markdown pane that has opened the created file, including panes without a save method. No asynchronous step precedes the final trash dispatch after that check. A dispatched host trash operation cannot be cancelled; retained artifacts are reported at their current paths with the cause.

Merge link preflight resolves WikiLinks and embeds from each original note through Metadata Cache, including aliases, heading/block fragments, transferred Text/List properties, and moved Markdown descendants. A link that resolves to the source Node Note being removed stops the merge before the first move or write. Fenced/indented code, inline code, and comments remain literal. The guard rejects unsafe links; it does not rewrite them. Ambiguous numbered-list fence openers and combined list/quote fence openers fail closed instead of assuming they hide links.

## Visual resolution

Visual Core accepts only a scalar string or flat string list. It classifies each entry as a base candidate, color modifier, or unknown: bases are Vault image wikilinks, Lucide icons in Obsidian's registry, or exactly one visible extended grapheme cluster. `lucide:` explicitly disambiguates a Lucide icon, while `color:` marks a foreground accent or fallback. Parsing retains order for diagnostics and resolution; the first valid color wins. VisualService resolves Metadata Cache and Vault resource URIs one base at a time, continuing locally after a missing image. A resolved glyph or Lucide receives the color as its foreground; resolved emoji and images preserve their native pixels without an added marker or container treatment. If every base candidate fails, color becomes a centered circular swatch. Nearest-ancestor lookup starts only after the local declaration is exhausted and never combines bases and colors across levels. Picker writes reject unknown or multi-grapheme values. Renderers add kind/script classes: glyphs use the Obsidian interface font, emoji use either the selected installed color font or the platform stack, and property-derived Explorer/title visuals occupy a fixed frameless slot. The imperative settings surface probes only a curated font-family list through local `FontFace` sources rather than enumerating all system fonts. RuntimeStyles injects the validated selected stack into every owned workspace-document stylesheet; a missing family falls through to the platform stack. The title slot remains outside editable text and receives measured first-line block and inline offsets plus resize-triggered recalculation. Advanced CSS variables remain available for overrides.

The Picker writes through `FileManager.processFrontMatter`: zero entries remove the property, one writes Text, and multiple write List. It refuses unknown, multi-grapheme, non-string, or nested values rather than silently accepting or losing data.

Visual edits capture the original folder, canonical note, paths, and `icon` value when the picker or cover menu opens. NodeService serializes the write and rechecks this binding and the active lifecycle inside the actual `processFrontMatter` callback. A replacement, rename, changed icon, or unload refuses the edit. Unload also invalidates open pickers; list reordering/deletion restores keyboard focus to a remaining row.

## Explorer and Contents

ExplorerAdapter binds surfaces only after `start`. Asynchronous reveal, observer callbacks, and delayed decoration belong to the run generation that created them; `stop` invalidates that generation, so a later host completion cannot reinstall surface resources even after the adapter restarts. Target visibility is checked again after asynchronous leaf materialization.

Animation settlement has a request-owned one-second safety ceiling. If an animation stalls or pauses after capture, expiry drops the request without scrolling; user takeover and disposal cancel the timer, and a late completion cannot revive it. Invisible toolbars and toolbars outside the target row's horizontal range do not reduce its viewport.

ExplorerAdapter discovers every `file-explorer` leaf and observes only that leaf's container, never `document.body`. It hides canonical notes and subtracts them plus currently invisible managed subtrees from real `TFolder.children` to decide whether a complete Folder Node is a visual leaf. A visual leaf adds only a removable dot class and owned `aria-hidden` to the existing disclosure control; host expansion state is never written. On virtualized Explorers, Manual mode projects only sibling order into the guarded host sorter while Name mode keeps native order. Ordinary refresh preserves the currently visible viewport anchor; an explicit host reveal (including native breadcrumb reveal) gets a separate actual-DOM viewport postcondition so the requested visible row is minimally corrected into view despite plugin-owned Root/hidden-row geometry. The visible viewport intersects ancestor clipping and the visual viewport, and excludes an overlapping mobile toolbar. Canonical Node Note reveal targets project to their folder row, property-hidden targets are not forced visible, and missing private host capabilities fall back without takeover. Batched mutation refresh restores the arrow when visible content appears. Each explicit reveal owns its native completion and a bounded next-render materialization opportunity, after any active finite drawer layout animation; older completions cannot settle a newer request. User input, changed target visibility, disposal, or that rendering boundary cancels unresolved correction. Desktop enables HTML5 drag, Android claims no draggable ownership, and `stop`/unload disconnects observers and listeners and restores every owned DOM element, attribute, class, order, sorter, and reveal function.

Contents View resolves the active file's owning folder and uses Root when no file is active. Each render queries direct children/files and shows only non-empty paged sections, or one unified empty state. Breadcrumbs exclude the current item and compact the middle of deep paths; the current card opens its Node Note. The Node Graph extension injects into the existing header action container instead of prepending a separate row. `sectionOpen` belongs only to the view instance, survives rerender and node changes, and disappears on close. Desktop retains drag helpers, Android has no drag ownership, and ordinary file/album/unmanaged-folder menus still emit the distinct `file-menu` source.

## Node Graph

The ItemView owns a child `Scope` of the app scope. A selective catch-all routes Ctrl/Cmd+Enter only when its Canvas, Canvas node body or DOM node body owns focus, before the host's global open-link shortcut can consume the event. It uses the same tooltip-dismissal/open path and suppresses repeat or composing activation. Alt+Enter routes only the existing Canvas or DOM expansion handle to its branch-toggle path. Other focus targets and chords fall through to the parent; closing the view makes its scoped handler inert, and focus is read from the view's owning document.

GraphIndex is owned by the Node Graph extension and reuses NodeService classification/order, property-driven subtree visibility, Metadata Cache, ReferenceIndex, and resolved Visuals. It records every visible managed node, directed parent-child structure, and resolved canonical-note link adjacency once, then consumes path-targeted RefreshBatch invalidations. It has no separate include/exclude rule layer. NodeService order is carried through topology and both layout dimensions; after an incremental refresh, cached parent-child relations are restored to full-build depth-first order without another Vault traversal, so a partial refresh and a fresh rebuild produce the same coordinates. Active-leaf changes, scope changes, search, expansion, 2D/3D switching, and the link toggle do not rebuild the Vault catalog. Rename remaps path-keyed view state atomically; delete removes stale state. This boundary remains local to Node Graph and does not replace the data paths used by Explorer or Contents.

ViewState separates serialized workspace fields from session state. After a manual expansion change, it derives visible IDs from VisibleScene; a hidden focus walks topology parents to the nearest visible ancestor before DOM, Canvas 2D, or Canvas 3D renders. Search uses its direct temporary expansion/focus snapshot path, so clearing still restores the exact pre-search state. Per-scope expansion remains a one-level baseline plus in-memory exceptions.

VisibleScene is the sole filtered model consumed by DOM, Canvas 2D, and Canvas 3D. Search summarizes matches in one linear pass, and the view computes only the active dimension's layout. Shared geometry owns card size, presentation, hit testing, parent/child handles, structure anchors, link-card edge anchors, and link curves. Cards are 72px tall for top-to-bottom layouts with coarse pointers and 46px otherwise; DOM and Canvas presentation, culling, hit regions, edges, and viewport fitting use that shared height, while dense DOM 3D dots remain 16px and Canvas dots retain their existing size. Structure edges retain explicit parent-to-child direction: from the parent's right handle to the child's left handle in left-to-right layouts, and from the parent's bottom handle to the child's top handle in top-to-bottom layouts. Link edges remain separate from handles and from the structural skeleton. Canvas preserves every visible structure edge and applies limits only to link edges, including focused incident links. Large 2D scenes retain a readable minimum scale and query a spatial index for viewport candidates while retaining required parent edge endpoints; large 3D scenes use dots whose hit areas match presentation and reveal complete cards only for focus or hover. The workspace Graph View directly owns its DOM viewport observer for the lifetime of that ItemView, while a separate toolbar renderer owns SearchComponent and toolbar DOM construction; the plugin layer no longer exists merely to proxy geometry lifecycle. Same-scope redraws retain viewport state and the live search editor, refresh every model-dependent toolbar field, replace viewport-button bindings, and reproject DOM 3D nodes and edges after restoring the camera. A successful retry of pending settings persistence reconciles the latest committed settings without submitting unfinished control text. Renderer status never becomes a graph-covering overlay, and all subscriptions, observers, animation frames, canvases, and DOM nodes are released on close or unload.

Canvas keyboard target selection lives in the pure `graphKeyboardTarget` helper. It consumes current 2D or projected 3D positions and stable scene order; the renderer owns focus, activation, and host events. Arrow keys use screen direction without wraparound, while Home and End retain scene order.

The Canvas image cache retains the complete visual working set actually drawn in the current viewport. Duplicate visuals share an image, failed loads remain cached, and leaving the viewport, palette changes, or destruction detach the corresponding load callbacks. Visible sets above 256 do not evict one another within a frame; load completions request coalesced redraws, while old resources cannot wake a replaced viewport. Hover tooltips measure their actual bounds before flipping and clamping to available space; long paths wrap, and right-to-left layouts prefer the pointer's left side.

Viewport changes dismiss the previous hover before drawing at the new size. Details that overflow the available height become a focusable, scrollable note beside the pointer, with height limited to the larger available vertical side so the trigger remains clickable. A 200 ms dismissal bridge lets the pointer cross empty space between the note and node overlay. Entering or focusing either region cancels dismissal; a new node resets both scroll axes, and Escape returns focus to the Canvas. Every pointer and keyboard open dismisses details and cancels their timer before calling the host. The timer belongs to the surface's document window and is cancelled on dismissal, resize and destruction; a destroyed renderer rejects retained callbacks. Unloading or restarting the plugin also invalidates pending reveal notifications, so cancellation cannot produce a late unavailable/error notice.

## Consistency and fail-closed behavior

Each Vault-event boundary first consumes OperationCoordinator's expected internal events; external rename events enter the same structural transaction queue. Native create/delete events refresh classification but do not auto-convert a note, complete its other half, or rebuild a deleted Node Note. External rename synchronizes the other half only for an unambiguous complete pair; an incomplete node renames only the side that exists. Each Workspace document has one capture-phase unresolved-link handler, including popout documents, without a body observer. It resolves Obsidian's new-note parent, respects unmanaged boundaries, and routes supported Markdown targets through `createNodePath`; missing explicit-path ancestors and the target Node share one undo stack. Explicit wikilink display text comes from Metadata Cache when available and is written only when the shared aliases setting is enabled. Selection creation pins the source TFile/path and source range. A shared asynchronous operation serves the default confirmation modal and the optional direct path. After NodeService creates the target, FileManager.generateMarkdownLink owns link syntax, path format, and disambiguation. A pure helper escapes literal Markdown labels and bare destination parentheses, preserves percent escapes and ordinary WikiLink display punctuation, and rejects WikiLink delimiter sequences that cannot preserve the label. The source classifier rejects cell/row crossings and the helper escapes only unescaped table pipes. Source identity, range, table context, and the live editor are rechecked before replacement; generation or replacement failure uses the existing creation receipt to roll back. RefreshScheduler combines visual work into one full or path-targeted batch, and GraphIndex consumes that same batch instead of starting an independent scan. Path collisions, cycles, changed selections, two canonical candidates after a folder rename, property conflicts, and merge frontmatter conflicts stop the operation. Optional bulk organization and explicit property migration scan asynchronously in batches, support cancellation, revalidate previews immediately before writing, validate complete results afterward, and roll back on failure. Every write modal refuses cancellation/close while submission is in flight. Plugin unload aborts confirmed work and prevents later forward mutation. Health combines both scans plus icon-shape diagnostics but owns no commit action. Production deployment, source tests, packaged candidates, and host acceptance remain separate evidence.
