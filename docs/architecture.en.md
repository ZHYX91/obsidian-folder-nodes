# Folder Nodes — Architecture

## Identity and persistence

A complete node's current identity is its normalized Vault folder path and `A/A.md` structure; no stable ID exists. Either side missing its folder or same-named Node Note is immediately classified as an incomplete node, without a second hidden identity or any initialization/adoption state. Folder Nodes actively uses `aliases`, `icon`, and one plugin-owned `folder-nodes` Text List. Its canonical tokens are `order=manual`, a positive integer `rank=N`, and `hidden=true`; defaults are absent and an empty list is removed. `aliases` and `icon` are shared content conventions, while `folder-nodes` is the plugin structural contract. Homepage preferences, icon placement, naming rules, exact unmanaged paths, and name-start rules stay in plugin `data.json`, never note YAML. A Node Graph leaf serializes only scope, focus, dimension, and whether links are shown in Obsidian workspace state. Per-scope branch expansion and active-search snapshots remain in memory for that leaf and are never written to `data.json`, note YAML, or restored after restart.

## Layers

The `folder-nodes` list is protected structural metadata and never copies from a merge source. NodeService `children()` continues to return the complete managed structure; visibility projections use `unmanaged || !hiddenNodesEnabled || showHiddenNodesThisSession || !effectiveHidden(node)` and walk upward to the nearest canonical or compatibility-read hidden source. Explorer, Contents, and Graph share that rule, with Graph pruning hidden subtrees before model and layout. Only the persistent master switch enters schema-v2 `data.json`; session reveal remains in memory. Schema 2 removes deprecated graph rule arrays without touching notes and reports how many entries were discarded.

Property resolution reads `folder-nodes` plus published legacy `folderNodeChildrenSort`, `folderNodeSiblingRank`, and `folderNodeHidden`. Equivalent dual values are redundant; conflicts and invalid known values fail closed. The source patcher owns only these exact top-level keys, detects duplicate/quoted/unterminated ambiguity, preserves BOM and line endings, retains unrelated YAML/body plus valid unknown future tokens, and writes canonical token order. Property migration is never a startup effect: its read-only scan fingerprints exact sources, an explicit commit rescans, pins TFile identity and the current unsaved editor where applicable, validates afterward, and rolls exact changed text back on failure.

Core handles only paths, naming, unmanaged-boundary rules, bulk-organization plans, reverse-reference indexing, sparse ordering, minimal frontmatter patches, Visual declaration parsing, and pure Node Graph visibility/geometry. Adapters encapsulate Vault, Metadata Cache, File Explorer, resource URIs, and Node operations; VaultOperationCoordinator separately owns structural-write serialization and internal-event attribution. Presentation contains the shared host-DOM renderer used by Explorer, Settings, and UI without reversing their layer boundaries. UI/App provides localization, settings, commands, menus, modals, Visual Picker, Contents View, Node Graph state/rendering, and batched refresh scheduling. Node Graph follows a bounded `GraphIndex → ViewState → VisibleScene → renderer` flow rather than introducing a plugin-wide data abstraction. UI/App also owns one content-fingerprinted constructable stylesheet per Workspace document, including Node Graph rules; the packaged `styles.css` is intentionally inert, so neither Obsidian's native stylesheet cache nor a second graph stylesheet becomes another runtime authority. One run-once layout gate registers with the host first and then checks `layoutReady`, closing the transition race without polling or delayed retries. The public repository does not depend on the local workspace or a personal Vault.

## Ordering engine

Natural mode uses Unicode-normalized, numeric-aware basename order and writes no token. On the first explicit manual placement, the parent Node writes `order=manual` in `folder-nodes`, and current direct Child Nodes materialize sparse `rank=N` tokens at gaps of 1024. An available gap patches only the moved node. Exhausted gaps rebalance at most 64 neighbors before falling back to rank materialization for that parent, but no child array is ever written into the parent Note. Reads compare valid rank, normalized basename, then path, so missing or duplicate ranks stay deterministic. Rename does not change the rank on a Child Note, and a new child under a manual parent takes an end rank.

## Node operations

NodeService treats create, rename, move, place, merge, repair, and trash as serialized structural transactions; every rename or move goes through Obsidian FileManager to preserve links. Move and placement reject self and descendants, and relative placement recomputes parent/index inside the same transaction. Each multi-step operation preflights cached and on-disk targets and keeps reverse-order rollback actions; an incomplete rollback returns an aggregate failure containing both the original and recovery errors instead of reporting success. Merge preflights target-path and frontmatter conflicts; target properties win, non-conflicting source properties join the target, source body is appended, resources move, and the source goes to system trash. Note-only move/delete is allowed and leaves the containing folder untouched. External rename reconciliation synchronizes an existing Node Note/folder pair in either direction, but never invents a missing Note. Root cannot be renamed, moved, or deleted as a complete node. New Node Notes are blank; Folder Nodes does not execute content templates.

Structural metadata patches use the current unsaved Markdown editor when exactly one matching view exists; otherwise they run through `Vault.process`. Both paths pin the original TFile and path, revalidate immediately before commit, and reject concurrent replacement or content changes. Rollback closures retain original object references and verify owned content before mutation. Settings persistence uses schema v2, migrates unversioned/schema-1 data once, and opens an invalid or newer explicit schema read-only without rewriting unknown fields. Its local serialized queue captures immutable snapshots, retains the latest failed snapshot for Retry, and appends one final compatible snapshot during unload so an older write cannot finish last.

## Visual resolution

Visual Core accepts only a scalar string or flat string list. It classifies each entry as a base candidate, color modifier, or unknown: bases are Vault image wikilinks, Lucide icons in Obsidian's registry, or exactly one visible extended grapheme cluster. `lucide:` explicitly disambiguates a Lucide icon, while `color:` marks a foreground accent or fallback. Parsing retains order for diagnostics and resolution; the first valid color wins. VisualService resolves Metadata Cache and Vault resource URIs one base at a time, continuing locally after a missing image. A resolved glyph or Lucide receives the color as its foreground; resolved emoji and images preserve their native pixels without an added marker or container treatment. If every base candidate fails, color becomes a centered circular swatch. Nearest-ancestor lookup starts only after the local declaration is exhausted and never combines bases and colors across levels. Picker writes reject unknown or multi-grapheme values. Renderers add kind/script classes: glyphs use the Obsidian interface font, emoji use either the selected installed color font or the platform stack, and property-derived Explorer/title visuals occupy a fixed frameless slot. The imperative settings surface probes only a curated font-family list through local `FontFace` sources rather than enumerating all system fonts. RuntimeStyles injects the validated selected stack into every owned workspace-document stylesheet; a missing family falls through to the platform stack. The title slot remains outside editable text and receives measured first-line block and inline offsets plus resize-triggered recalculation. Advanced CSS variables remain available for overrides.

The Picker writes through `FileManager.processFrontMatter`: zero entries remove the property, one writes Text, and multiple write List. It refuses unknown, multi-grapheme, non-string, or nested values rather than silently accepting or losing data.

## Explorer and Contents

ExplorerAdapter encapsulates the File Explorer host boundary: it discovers every `file-explorer` leaf and observes only that leaf's container, never `document.body`. Each surface uses its own Document, MutationObserver, ResizeObserver where available, AbortController, and listeners, so the main window and popout windows remain isolated; decoration requests are batched. The adapter inserts one idempotent pinned Root row with a trailing session-visibility eye, hides canonical notes, places or hides Node Visuals before/after names, performs guarded reveal, and recognizes disclosure controls. The eye is present only while hidden-marker application is enabled, reflects reveal state through icon and `aria-pressed`, and toggles without opening Root or writing YAML. A desktop capability flag enables HTML5 drag listeners, draggable ownership, and before/into/after placement. Android keeps the same decoration and click behavior without registering drag listeners or claiming draggable ownership. The adapter adds a distinct New node action but does not hide Obsidian's native New note or New folder controls. A note-title icon is a non-editable sibling of `.inline-title`, never a child of editable title text. `stop`/unload disconnects observers and listeners, removes all owned DOM/classes, and restores owned draggable attributes and Explorer order. Explorer and Contents both delegate structural placement to NodeService.

Contents View resolves the current node to the active file's owning folder and uses Root when no file is active. The Root Node Note path is the sanitized Vault name at the Vault root. The View queries only direct children and files; Nodes, Album, and Files paginate independently in batches of 200. Core ReferenceIndex maintains reverse reference counts incrementally from metadata events, so rendering never traverses all Vault `resolvedLinks`. Desktop-only interaction helpers define internal drag MIME, supported payload, and drop zones. Android creates no drag handles, sources, or targets and keeps the centrally built Move, Move up, and Move down actions plus native folder move. After a native cross-parent folder rename, NodeService appends a fresh child rank when the target parent is manually sorted so a source-parent rank cannot disturb the target order. Healthy Folder Node menus keep only Open, Open in new tab, Create child, and Folder Nodes actions at the first level; the last opens one grouped, touch-friendly action panel shared by Contents, Graph, native folder, and Node Note surfaces. Native folder/note operations stay untouched and redundant actions are filtered per surface. Problem Node menus remain direct and repair-focused. These owned menus do not trigger `file-menu`; ordinary files, Album entries, and unmanaged folders trigger it with a distinct source so other plugins can extend those entry menus without duplicating Folder Nodes' own actions. Album images load from Vault resource URIs into a non-DOM `Image` from the owning window and draw once to canvas; rerender/onClose cancels unfinished loads. Every format including GIF remains static without reading Vault binary, and video/audio never create playback elements.

## Node Graph

GraphIndex is owned by the Node Graph extension and reuses NodeService classification/order, property-driven subtree visibility, Metadata Cache, ReferenceIndex, and resolved Visuals. It records every visible managed node, directed parent-child structure, and resolved canonical-note link adjacency once, then consumes path-targeted RefreshBatch invalidations. It has no separate include/exclude rule layer. NodeService order is carried through topology and both layout dimensions; after an incremental refresh, cached parent-child relations are restored to full-build depth-first order without another Vault traversal, so a partial refresh and a fresh rebuild produce the same coordinates. Active-leaf changes, scope changes, search, expansion, 2D/3D switching, and the link toggle do not rebuild the Vault catalog. Rename remaps path-keyed view state atomically; delete removes stale state. This boundary remains local to Node Graph and does not replace the data paths used by Explorer or Contents.

ViewState separates serialized workspace fields from session state. Workspace migration reads the former relation mode only at the boundary: Structure becomes `showLinks: false`, and Links or Hybrid becomes `showLinks: true`; new views default to false. Per-scope expansion uses a one-level baseline plus expanded/collapsed branch exceptions in memory. Search overlays a temporary ancestor expansion and retains the prior expansion, focus, and camera snapshot until cleared. Global, Subtree, and Local scope reducers produce the structural universe before layout; Local includes one parent context but expands only through the selected node's subtree, and only an enabled link overlay adds direct link neighbors.

VisibleScene is the sole filtered model consumed by DOM, Canvas 2D, and Canvas 3D. Search summarizes matches in one linear pass, and the view computes only the active dimension's layout. Shared geometry owns card size, presentation, hit testing, parent/child handles, structure anchors, link-card edge anchors, and link curves. Structure edges retain explicit parent-to-child direction: from the parent's right handle to the child's left handle in left-to-right layouts, and from the parent's bottom handle to the child's top handle in top-to-bottom layouts. Link edges remain separate from handles and from the structural skeleton. Canvas preserves every visible structure edge and applies limits only to link edges, including focused incident links. Large 2D scenes retain a readable minimum scale and query a spatial index for viewport candidates while retaining required parent edge endpoints; large 3D scenes use dots whose hit areas match presentation and reveal complete cards only for focus or hover. Renderer status never becomes a graph-covering overlay, and all subscriptions, observers, animation frames, canvases, and DOM nodes are released on close or unload.

## Consistency and fail-closed behavior

Each Vault-event boundary first consumes OperationCoordinator's expected internal events; external rename events enter the same structural transaction queue. Native create/delete events refresh classification but do not auto-convert a note, complete its other half, or rebuild a deleted Node Note. External rename synchronizes the other half only for an unambiguous complete pair; an incomplete node renames only the side that exists. Each Workspace document has one capture-phase unresolved-link handler, including popout documents, without a body observer. It resolves Obsidian's new-note parent, respects unmanaged boundaries, and routes supported Markdown targets through `createNodePath`; missing explicit-path ancestors and the target Node share one undo stack. Explicit wikilink display text comes from Metadata Cache when available and is written only when the shared aliases setting is enabled. Selection creation pins the source TFile/path and source range; its pure source classifier escapes the wikilink separator inside one table cell and rejects cell/row crossings. RefreshScheduler combines visual work into one full or path-targeted batch, and GraphIndex consumes that same batch instead of starting an independent scan. Path collisions, cycles, changed selections, two canonical candidates after a folder rename, property conflicts, and merge frontmatter conflicts stop the operation. Optional bulk organization and explicit property migration scan asynchronously in batches, support cancellation, revalidate previews immediately before writing, validate complete results afterward, and roll back on failure. Every write modal refuses cancellation/close while submission is in flight. Plugin unload aborts confirmed work and prevents later forward mutation. Health combines both scans plus icon-shape diagnostics but owns no commit action. Production deployment, source tests, packaged candidates, and host acceptance remain separate evidence.
