# Folder Nodes architecture

## Identity and persistence

A complete node's current identity is its normalized Vault folder path and `A/A.md` structure; no stable ID exists. A folder without the same-named Note is a valid folder-only shell but does not acquire a separate hidden identity. Folder Nodes actively uses `aliases`, `icon`, `folderNodeChildrenSort`, and `folderNodeSiblingRank`. `aliases` and `icon` are portable content properties; the two `folderNode` fields are plugin structural properties. Managed, Migrating, and Unadopted state, homepage preferences, icon placement, naming rules, exact unmanaged paths and name-prefix rules stay in plugin `data.json`.

## Layers

Core handles only paths, naming, unmanaged-boundary rules, migration plans, reverse-reference indexing, sparse ordering, minimal frontmatter patches, and Visual declaration parsing. Adapters encapsulate Vault, Metadata Cache, File Explorer, resource URIs, and Node operations; VaultOperationCoordinator separately owns structural-write serialization and internal-event attribution. Presentation contains the shared host-DOM renderer used by Explorer, Settings, and UI without reversing their layer boundaries. UI/App provides localization, settings, commands, menus, modals, Visual Picker, Contents View, and batched refresh scheduling. The public repository does not depend on the local workspace or a personal Vault.

## Ordering engine

Natural mode uses Unicode-normalized, numeric-aware basename order and writes no property. On the first explicit manual placement, the parent Node writes `folderNodeChildrenSort: manual` and current direct Child Nodes materialize `folderNodeSiblingRank` at gaps of 1024. An available gap patches only the moved node. Exhausted gaps rebalance at most 64 neighbors before falling back to rank materialization for that parent, but no child array is ever written into the parent Note. Reads compare valid rank, normalized basename, then path, so missing or duplicate ranks stay deterministic. Rename does not change the rank on a Child Note, and a new child under a manual parent takes an end rank.

## Node operations

NodeService treats create, rename, move, place, merge, repair, and trash as serialized structural transactions; every rename or move goes through Obsidian FileManager to preserve links. Move and placement reject self and descendants, and relative placement recomputes parent/index inside the same transaction. Each multi-step operation preflights cached and on-disk targets and keeps reverse-order rollback actions; an incomplete rollback returns an aggregate failure containing both the original and recovery errors instead of reporting success. Merge preflights target-path and frontmatter conflicts; target properties win, non-conflicting source properties join the target, source body is appended, resources move, and the source goes to system trash. Note-only move/delete is allowed and leaves the containing folder untouched. External rename reconciliation synchronizes an existing Node Note/folder pair in either direction, but never invents a missing Note. Root cannot be renamed, moved, or deleted as a complete node. New Node Notes are blank; Folder Nodes does not execute content templates.

Structural metadata patches use the current unsaved Markdown editor when exactly one matching view exists; otherwise they run through `Vault.process`. Both paths pin the original TFile and path, revalidate immediately before commit, and reject concurrent replacement or content changes. Rollback closures retain original object references and verify owned content before mutation. Settings persistence captures immutable snapshots and serializes saves so an older write cannot finish after a newer one.

## Visual resolution

Visual Core accepts only a scalar string or flat string list. It classifies each entry as a base candidate, color modifier, or unknown: bases are Vault image wikilinks, Lucide icons in Obsidian's registry, or exactly one visible extended grapheme cluster. `lucide:` explicitly disambiguates a Lucide icon, while `color:` marks an accent. Parsing retains order for diagnostics and resolution; the first valid color wins. VisualService resolves Metadata Cache and Vault resource URIs one base at a time, continuing locally after a missing image; color alone becomes a swatch. Nearest-ancestor lookup starts only after the local declaration is exhausted and never combines bases and colors across levels. Picker writes reject unknown or multi-grapheme values. Renderers add kind/script classes: glyphs use the Obsidian interface font, emoji use a platform color-emoji stack, and property-derived Explorer/title visuals occupy a fixed bordered badge. The title badge remains outside editable text and receives measured first-line block and inline offsets plus resize-triggered recalculation. Advanced CSS variables expose fonts and badge tokens without adding a settings font picker.

The Picker writes through `FileManager.processFrontMatter`: zero entries remove the property, one writes Text, and multiple write List. It refuses unknown, multi-grapheme, non-string, or nested values rather than silently accepting or losing data.

## Explorer and Contents

ExplorerAdapter encapsulates the File Explorer host boundary: it discovers every `file-explorer` leaf and observes only that leaf's container, never `document.body`. Each surface uses its own Document, MutationObserver, ResizeObserver where available, AbortController, and listeners, so the main window and popout windows remain isolated; decoration requests are batched. The adapter inserts one idempotent pinned Root row, hides canonical notes, places or hides Node Visuals before/after names, performs guarded reveal, recognizes disclosure controls, and maps drag zones to before, into, and after placement. It adds a distinct New node action but does not hide Obsidian's native New note or New folder controls. A note-title icon is a non-editable sibling of `.inline-title`, never a child of editable title text. `stop`/unload disconnects observers and listeners, removes all owned DOM/classes, and restores owned draggable attributes and Explorer order. Explorer and Contents both delegate structural placement to NodeService.

Contents View resolves the current node to the active file's owning folder and uses Root when no file is active. The Root Node Note path is the sanitized Vault name at the Vault root. The View queries only direct children and files; Nodes, Album, and Files paginate independently in batches of 200. Core ReferenceIndex maintains reverse reference counts incrementally from metadata events, so rendering never traverses all Vault `resolvedLinks`. Pure UI interaction helpers define the internal drag MIME, supported payload, three-part zone, and keyboard-menu gestures; the View owns only one drag session and one drop marker. Node drops invoke structural placement; a single ordinary-file drop calls FileManager-backed `moveFile` and accepts only into placement. Multi-selection inserts or copies links; dragging multiple selected items exports link text and never performs a partial multi-file move. The App layer centrally builds menu actions. Healthy and problem Node menus remain Folder Nodes-owned and do not trigger `file-menu`; ordinary files, Album entries, and unmanaged folders trigger it with a distinct source so other plugins can extend those entry menus without duplicating Folder Nodes' own actions. Album images load from Vault resource URIs into a non-DOM `Image` from the owning window and draw once to canvas; rerender/onClose cancels unfinished loads. Every format including GIF remains static without reading Vault binary, and video/audio never create playback elements.

## Consistency and fail-closed behavior

Managed state consumes OperationCoordinator's expected internal events at each Vault-event boundary; external rename events enter the same structural transaction queue. Native create/delete events refresh state but do not auto-convert notes or rebuild deleted Node Notes. Each Workspace document has one capture-phase unresolved-link handler, including popout documents, without a body observer. It resolves Obsidian's new-note parent, respects managed boundaries, and routes supported Markdown targets through `createNodePath`; missing explicit-path ancestors and the target Node share one undo stack. Explicit wikilink display text comes from Metadata Cache when available and is written only when the shared aliases setting is enabled. Selection creation pins the source TFile/path and source range; its pure source classifier escapes the wikilink separator inside one table cell and rejects cell/row crossings. RefreshScheduler combines visual work into one full or path-targeted batch. Startup validation is read-only. Path collisions, cycles, changed selections, two canonical candidates after a folder rename, and merge property conflicts stop the operation. Initialization/migration revalidates the preview signature immediately before writing, validates the complete result afterward, and rolls back on failure; every write modal refuses cancellation/close while submission is in flight. Plugin unload aborts a confirmed migration and prevents later forward mutation. Entering `migrating` is transactional: if that first settings save fails, the previous in-memory adoption state is restored and migration never starts. Health owns no commit action. Production deployment, source tests, packaged candidates, and host acceptance remain separate evidence.
